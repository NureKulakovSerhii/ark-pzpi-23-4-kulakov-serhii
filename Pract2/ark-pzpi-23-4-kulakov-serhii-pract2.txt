	3 ОПИС ВИКОНАНОЇ РОБОТИ
	Рефакторинг - це процес покрокових змін у структурі коді без зміни його зовнішнтої поведінки, з метою зробити код більш чистим, зрозумілим і легким для підтримки. Основні цілі рефакторингу:
	- покращення читабельності коду - код має бути легким для розуміння іншими розробниками і самим автором через деякий час після написання ділянки коду;
	- зменшення дублювання коду - повторюваний код винести у окремі функції або методи;
	- полегшення підтримки та розширення коду - після рефакторингу додавання нових функціональностей або виправлення помилок стає простішим і менш ризикованим;
	- підвищення якості коду - зменшується ймовірність помилок, покращується структура і логіка програми.
	Для рефакторингу PHP коду була обрана Лабораторна робота №2 з дисципліни “Скриптові мови програмування” за другий  курс навчання. Методи рефакторингу: Extract Method, Rename Method, Replace Conditional With Polymorphism.
	Extract Method (Виділення методу) - це прийом, що полягає у винесенні логічно цілісної частини коду в окремий новий метод, який отримує зрозумілу назву, що описує його функцію, а в початковому місці залишається лише виклик нового методу.
	Проблема: у коді зустрічалися повторювані блоки логіки, наприклад, підрахунок пробілів для вирівнювання виводу товарів у консолі. Код був дубльований у кількох місцях, що ускладньовало підтримку.

// Новий метод
function repeatSpaces($count) {
    $spaces = '';
    for ($i = 0; $i < $count; $i++) {
        $spaces .= ' ';
    }
    return $spaces;
}
// Виклик новостворенного методу замість обчислення пробілів для кожної ситуації окремо
function showProducts($products) {
    $max_length = 0;
    foreach ($products as $product) {
        $length = mb_strlen($product['name']);
        if ($length > $max_length) {
            $max_length = $length;
        }
    }
    $spaces = '';
    for ($i = 0; $i < 15; $i++){
        $spaces .= ' ';
    }
    echo "№  НАЗВА" . repeatSpaces(15) . "  ЦІНА\n";
    
    foreach ($products as $product) {
        $spaces = repeatSpaces($max_length - mb_strlen($product['name']) + 2);
        echo $product['id'] . "  " . $product['name'] . $spaces . $product['price'] . "\n";
    }
    echo "   " . str_repeat("-", 11) . "\n";
    echo "0  ПОВЕРНУТИСЯ\n";

	Rename Method (Метод Перейменування) - це прийом, що покращує читабельність коду шляхом зміни імені методу таким чином, щоб воно максимально точно відображало його призначення, при цьому не змінюючи його функціональність.
	Проблема: під час аналізу коду  консольного застосунку після тривалої перерви було виявлено метод із неінформативною назвою “add”, яка не відображала його реального призначення. Назва методу була занадто загальною та змушувала переглядати реалізацію та витрачати час, щоб зрозуміти, яку саму дію цей метод виконує.

function add(&$user, $product, $quantity) {
    if ($quantity === 0) {
        foreach ($user['cart'] as $key => $item) {
            if ($item['product']['id'] === $product['id']) {
                unset($user['cart'][$key]);
                $user['cart'] = array_values($user['cart']);
                return;
            }
        }
        return;
    }
    foreach ($user['cart'] as &$item) {
        if ($item['product']['id'] === $product['id']) {
            $item['quantity'] += $quantity;
            return;
        }
    }
    
    $user['cart'][] = [
        'product' => $product,
        'quantity' => $quantity
    ];
}
	Вирішення проблеми: як можна побачити, представлений метод працює з товарами, і виконує різний функціонал в залежності від вхідних параметрів. Якщо в кошику користувача немає заданого товару, при виклику методу товар буде додано у заданій користувачем кількості. Якщо товар вже є у кошику - кількість цього товару збільшиться. Якщо ж користувач вкаже параметр “quantity” дорівнює 0 - товар видалитсья з кошику. Тож, ім’я методу невірно трактує його функціонал і доречним буде перейменувати метод в “manageCartItem”, для уникання плутанини у інших розробників, а також у автора коду після спливу часу.
	Код після рефакторингу:
function manageCartItem(&$user, $product, $quantity) {
    if ($quantity === 0) {
        foreach ($user['cart'] as $key => $item) {
            if ($item['product']['id'] === $product['id']) {
                unset($user['cart'][$key]);
                $user['cart'] = array_values($user['cart']);
                return;
            }
        }
        return;
    }
    foreach ($user['cart'] as &$item) {
        if ($item['product']['id'] === $product['id']) {
            $item['quantity'] += $quantity;
            return;
        }
    }
    
    $user['cart'][] = [
        'product' => $product,
        'quantity' => $quantity
    ];
}
	Replace Conditional With Polymorphism (Заміна умовного оператора поліморфізмом) - це прийом, який полягає у заміні складних умовних конструкцій (if/else або switch) на використання поліморфізму, коли різна поведінка програми інкапсулюється у окремі класи. Такий підхід покращує читабельність коду, спрощує його розширення та зменшує залежність від умовних операторів.
	Проблема: У початковій реалізації консольного застосунку обробка дій користувача реалізована за допомогою великої конструкції switch, яка аналізує введену команду ($input) і виконує відповідну логіку. Кожна гілка case містить власний, досить об’ємний код:
	- завершення програми (case “0”),
	- робота з товарами та кошиком (case “1”),
	- перегляд кошика (case “2”),
	- робота з профілем користувача (case “3”).

	Вирішення проблеми: для усунення залежності від оператора switch було використано прийом Replace Conditional With Polymorphism. Суть рішення полягає у тому, що кожна команда користувача була винесена в окремий клас, який інкапсулює власну логіку виконання. Для цього було створено спільний інтерфейс Command з методом execute(), який кожна конкретна команда реалізує у власному класі, відповідальному лише за свою поведінку. Замість громіздкої конструкції switch використовується асоціативний масив команд, де ключем є введене користувачем значення, а значенням - відповідний об’єкт команди. Після цього виконання потрібної дії зводитсья до виклику методу execute() у відповідного об’єкта. Такий підхід дозволив:
	- позбутися великої умовної конструкції;
	- чітко роздалити відповідальність між окремими класами;
	- спростити читабельність основного циклу програми;
	- полегшити розширення функціоналу, оскільки додавання нової команди не потребує модифікації існуючої логіки, а лише створення нового класу.

В.2 Програмний код після рефакторингу:
interface Command {
    public function execute();
}
class ExitCommand implements Command {
    public function execute() {
        exit;
    }
}
class ShowProductsCommand implements Command {
    private array $products;

    public function __construct(array $products) {
        $this->products = $products;
    }

    public function execute() {
        showProducts($this->products);
    }
}
class ShowCartCommand implements Command {
    private array $cart;

    public function __construct(array $cart) {
        $this->cart = $cart;
    }

    public function execute() {
        showCart($this->cart);
    }
}
class ProfileCommand implements Command {
    private array &$user;

    public function __construct(array &$user) {
        $this->user = &$user;
    }

    public function execute() {
        setUserProfile($this->user);
    }
}
$commands = [
    "0" => new ExitCommand(),
    "1" => new ShowProductsCommand($products),
    "2" => new ShowCartCommand($user['cart']),
    "3" => new ProfileCommand($user),
];

$input = trim(fgets(STDIN));

if (isset($commands[$input])) {
    $commands[$input]->execute();
} else {
    echo "ПОМИЛКА! Введіть правильну команду\n";
}
